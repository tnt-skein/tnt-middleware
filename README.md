# tnt-middleware

Конвейер слоёв обработки для Tarantool: журнал, замер времени, перехват
отказа, опознаватель запроса, межсайтовые заголовки и свои слои живут
вокруг обработчика, отдельно от дела. Один и тот же механизм годится
и входящему запросу, и исходящему — о виде запроса и ответа конвейер
ничего не знает.

```lua
local middleware = require('tnt.middleware')

-- опознаватель, перехват отказа и запись о проходе вокруг обработчика
local handle = middleware.chain({ 'request_id', 'rescue', 'log' }):wrap(function(request)
    return { status = 200, body = 'привет' }
end)

local response, err = handle({ method = 'GET', path = '/customers/7' })

-- межсайтовые заголовки под /api: чужим страницам — только по списку
local chain = middleware.chain({
    'request_id',
    { 'cors', { origins = { 'https://app.example.org' }, methods = { 'PUT' } }, path = '/api' },
    'log',
})
chain:without('log')
```

Зависимости: `tnt-clock` (монотонные часы замера), `tnt-context`
(контекст файбера с опознавателем запроса), `tnt-id` (ULID), `tnt-log`
(журнал готовых слоёв), `tnt-must` (проверка настроек слоя `cors`
и бросок отказа объявления без места) и `tnt-external` (подмена часов
и выдачи опознавателей в проверках).

## Зачем

Каждому запросу нужно одно и то же: записать в журнал, замерить время,
проверить вход, поймать падение обработчика. Писать это в каждом
обработчике — значит однажды забыть. Пакет делает шесть вещей:

- **Слой — обёртка, а не пара хуков**: получает `next` и сам решает,
  звать его, не звать или позвать несколько раз — на этом держатся
  проверка входа, замер и повтор.
- **Цепочка не бросает и не возвращает пустоты**: упавший слой
  и слой, забывший `return next(context)`, становятся отказом парой
  `nil, err`, который называет слой по имени; отказ упавшего несёт
  ещё и стек места броска полем `traceback`, а брошенное как есть —
  полем `raised`: отказ, брошенный обработчиком нарочно, отвечает тем
  же, чем ответил бы парой. Бросает она только
  на ошибке объявления, и место в исключении — строка приложения,
  позвавшая вход пакета, а не строка внутри него.
- **Слои именуются и переставляются**: `before`, `after`, `without`
  правят чужую готовую цепочку одной строкой.
- **Слой ставится с фильтром** по началу пути и способу запроса:
  `{ 'cors', { ... }, path = '/api' }`, `{ 'limit', { ... }, path = '/login', method = 'POST' }`.
- **Опознаватель запроса — от заголовка до заголовка**: ULID или
  пришедший, в контексте файбера для каждой записи журнала и в ответе
  заголовком `x-request-id`.
- **Межсайтовые запросы — готовым слоем**: список источников, точных
  и образцом поддомена, ответ на предварительный `OPTIONS` без
  обработчика, строгие умолчания; `*` вместе с учётными данными
  отвергается при сборке.

## Установка

```sh
tt rocks install tnt-middleware --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-middleware.git
cd tnt-middleware && tt rocks make
```

## Как пользоваться

| Вызов | Что делает |
|---|---|
| `chain(entries)` | цепочка из записей общего реестра |
| `configure(opts)` | общий реестр: `tag`, `layers` (фабрики), `groups` |
| `register(name, factory)`, `group(name, entries)` | объявить слой или группу |
| `new(opts)` | отдельный реестр со своими объявлениями |
| `status()` | что объявлено: `{ tag, layers, groups }` |
| `layer.<имя>(opts)` | готовые слои без реестра |

У цепочки — `wrap(handler)`, `run(context, handler)`, `use`, `before`,
`after`, `insert`, `without`, `clone`, `names`, `index_of`.

Готовые слои:

| Слой | Что делает |
|---|---|
| `request_id` | выдаёт опознаватель или принимает пришедший (`take`) и ведёт остаток цепочки в области контекста с ним |
| `request_id_header` | кладёт тот же опознаватель в ответ заголовком `x-request-id` |
| `log` | одна запись о проходе: описание запроса (`describe`), код ответа, длительность |
| `timing` | замер времени прохода — в контекст и приёмнику `observe` |
| `rescue` | пишет об отказе один раз (`warn` — ожидаемый, `error` — поломка) и по `respond` делает из него ответ |
| `cors` | разрешает чужим страницам читать ответы по списку `origins`; `methods`, `headers`, `expose`, `max_age`, `credentials` — только названное; на предварительный `OPTIONS` отвечает сам |

Слой объявляется фабрикой, и одна фабрика даёт два слоя с разной настройкой:

```lua
middleware.configure({
    tag = 'app.http',
    layers = { limit = limiter_factory },
    groups = { web = { 'request_id', 'rescue', 'log' } },
})

local chain = middleware.chain({
    'web',
    { 'limit', { per_process = 1000 }, name = 'limit_all' },
    { 'limit', { per_process = 10 }, name = 'limit_login', path = '/login', method = 'POST' },
})
```

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov, рок http и зависимости пакета в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
```

Покрытие строк — 100 %, убитых мутантов — 100 % (231 проверка,
467 мутантов в тринадцати модулях). Часы и выдача опознавателей подменены
в проверках, записи журнала ловит ловушка на `tnt-log`; настоящие ULID
и контекст файбера проверяются настоящими, место каждой записи слоёв —
в дочернем процессе с настоящим журналом ядра, а межсайтовые заголовки —
ещё и по сети, на живом `http.server`.
